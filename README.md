# 명지전문대학 장학금 & 수당 계좌 등록(지급) · 학생용

학생이 장학금·수당 지급용 계좌를 온라인으로 신청하고, 담당자가 신청내역을 조회·엑셀 다운로드하는 시스템입니다.

- **화면**: GitHub Pages (무료 정적 호스팅)
- **데이터·첨부파일**: Supabase (PostgreSQL DB + 비공개 파일 저장소, 서울 리전)
- 외부 라이브러리·CDN 없이 동작합니다. (브라우저 → Supabase 외 다른 서버로 통신하지 않음)

```
학생 ──(신청서 + 통장 사본[선택])──▶ index.html ──▶ Supabase  [추가만 가능, 조회 불가]
담당자 ──(로그인)─────────────────▶ admin.html ──▶ Supabase  [관리자만 조회·다운로드]
```

---

## 1. 폴더 구성

| 파일 | 설명 |
|---|---|
| `index.html` | 학생 신청 화면 (로그인 없이 신청) |
| `admin.html` | 관리자 화면 (학생 화면에는 링크가 없습니다) |
| `assets/config.js` | **설정 파일** – Supabase 주소·키, 지급구분, 학과·은행 목록 |
| `assets/apply.js` | 신청 화면 동작 |
| `assets/admin.js` | 관리자 화면 동작 (사업·대회 관리, 조회, 상태 변경, 엑셀·ZIP 다운로드, 작업 기록) |
| `assets/sb.js` | Supabase 연결 (fetch 기반 최소 클라이언트) |
| `assets/xlsx.js` | 엑셀(.xlsx)·ZIP 생성기 |
| `assets/common.js`, `assets/style.css` | 공통 기능·디자인 |
| `supabase/schema.sql` | **DB·보안 규칙 설정 스크립트** (Supabase에서 1회 실행) |

## 2. 설치 (약 20분)

### 2-1. Supabase 프로젝트
1. <https://supabase.com> 가입(학교 업무용 계정 권장) → **New project**
2. **Region: Northeast Asia (Seoul)** 선택, DB 비밀번호는 안전하게 보관
3. **SQL Editor → New query** → `supabase/schema.sql` 전체 붙여넣기 → **Run**
   - 테이블 4개(`programs`, `applications`, `admins`, `admin_logs`)와 비공개 저장소(`student-docs`)가 만들어집니다.

> 이전 버전(학생증·이메일 인증 포함) 스크립트를 이미 실행했다면, 새 프로젝트를 만들어 설치하는 것이 가장 깔끔합니다.

### 2-2. 관리자 계정
1. **Authentication → Sign In / Providers**에서 **"Allow new users to sign up" 끄기** (아무나 계정을 만들지 못하게)
2. **Authentication → Users → Add user → Create new user** (이메일·비밀번호, **Auto Confirm User** 체크)
3. **SQL Editor**에서 실행(이메일만 바꿔서):
   ```sql
   insert into public.admins (user_id, name)
   select id, '장학담당' from auth.users where email = 'admin@mjc.ac.kr';
   ```
   > 로그인 계정이 있어도 `admins`에 등록되지 않으면 신청내역을 볼 수 없습니다.

### 2-3. 설정 파일
**Project Settings → API Keys**에서 복사해 `assets/config.js`에 입력:
```js
SUPABASE_URL: "https://abcdefghijkl.supabase.co",
SUPABASE_KEY: "sb_publishable_xxxxxxxx",   // publishable 또는 anon 키
CONTACT: "문의: 학생처 장학팀 02-300-0000",
```
> ⚠ **publishable / anon 키만** 넣으세요(공개돼도 되는 키, 보안은 DB 규칙이 담당).
> **secret / service_role 키는 절대 넣거나 GitHub에 올리지 마세요.**

### 2-4. GitHub Pages
1. GitHub **New repository** (예: `mjc-scholarship-account`, 무료 계정은 **Public**)
   - 저장소에는 코드만 있고 개인정보는 없습니다.
2. 이 폴더의 파일 전체 업로드(**Add file → Upload files**, `.nojekyll` 포함)
3. **Settings → Pages** → Source: **Deploy from a branch**, Branch: **main / (root)** → Save
4. 1~2분 후 주소 생성
   - 학생용: `https://<깃허브아이디>.github.io/mjc-scholarship-account/`
   - 관리자: `https://<깃허브아이디>.github.io/mjc-scholarship-account/admin.html`

### 2-5. 개통 전 점검
- [ ] 학생 화면에 빨간 "설정이 완료되지 않았습니다" 안내가 **없다**
- [ ] 관리자 화면 **사업·대회 관리**에서 테스트 사업을 등록 → 학생 화면 목록에 나타난다
- [ ] 테스트 신청 → "신청이 접수되었습니다" + 접수번호 표시
- [ ] 관리자 로그인 → 방금 신청 건이 보이고, 통장 사본이 열린다
- [ ] 엑셀·ZIP 다운로드가 되고 작업 기록에 남는다
- [ ] 테스트 건 삭제

## 3. 운영 안내

### 사업·대회 등록 ★
관리자 화면 → **사업·대회 관리** 탭에서 등록합니다. 학생은 직접 입력할 수 없고, 지급 구분을 고르면 **모집중**인 사업·대회만 목록에 나옵니다.
- **신청기간**: 시작일·마감일을 넣으면 그 기간에만 보입니다(비우면 상시). 날짜는 한국 시간 기준입니다.
- **마감 / 재개**: 버튼 하나로 학생 화면에서 숨기거나 다시 보이게 합니다.
- **수정**: 이름·기간을 바꿀 수 있습니다. 이미 접수된 신청서에는 **신청 당시 이름**이 그대로 남습니다.
- **삭제**: 신청이 한 건이라도 있으면 삭제되지 않습니다(마감을 사용하세요).
- 선택한 지급 구분에 모집중인 사업·대회가 없으면, 학생은 사업 선택 없이 신청할 수 있습니다.
- 마감된 사업으로 제출하면 DB가 거부하고, 학생에게 다시 선택하라는 안내가 나옵니다.

### 계좌 변경 ★
학생은 신청 내역을 볼 수도, 고칠 수도 없습니다. 계좌를 바꾸려면 **다시 신청**합니다.
관리자 화면은 학번별 **최근 신청**을 기준으로 보여 주고, 이전과 계좌가 다르면 **[계좌변경]** 표시가 붙습니다.
→ 본인 인증이 없으므로 **남이 학번·이름을 알고 계좌를 바꿔 신청했을 수 있습니다. 반드시 본인 확인(전화 등) 후 '확인완료'** 로 처리하세요.

### 신청 제한
같은 학번은 **하루 5회**까지 신청할 수 있습니다(장난·대량 신청 방지).

### 처리 상태
`접수` → `확인완료` 또는 `반려` (메모 입력 가능). 관리자도 학생이 입력한 계좌번호 자체는 수정할 수 없습니다(원본 보존).

### 다운로드
- **엑셀**: 현재 조회 결과/전체, 계좌번호 전체/일부 가림 선택
- **ZIP**: 학생별 폴더에 통장 사본 + 신청내역 엑셀
- 모든 다운로드·상세 조회·상태 변경·삭제는 **작업 기록**에 남고, 기록은 수정·삭제할 수 없습니다.

### 관리자 추가·삭제, 비밀번호 분실
- 추가: 2-2의 2~3단계 반복
- 삭제: `delete from public.admins where user_id = (select id from auth.users where email='...');`
- 비밀번호 분실: **Authentication → Users**에서 재설정

### 보관기간 경과 자료 삭제
`supabase/schema.sql` 하단 SQL로 대상 확인 → 관리자 화면에서 삭제(통장 사본도 함께 삭제됨).

### 학과·지급구분 변경
- 학과: `assets/config.js`의 `DEPTS` 수정 후 GitHub에 다시 올리기
- 지급구분: `config.js`의 `PAY_TYPES`와 `schema.sql`의 `pay_type` 조건 **두 곳(programs, applications)** 을 함께 바꾸고 SQL 재실행

## 4. 보안 구조

| 대상 | 할 수 있는 것 | 할 수 없는 것 |
|---|---|---|
| 학생(로그인 없음) | 모집중인 사업·대회 목록 보기, 신청서 추가, 통장 사본 업로드(새 파일만) | 신청 조회·수정·삭제(본인 것 포함), 상태·사업명 지정, 사업·대회 등록 |
| 로그인했지만 `admins` 미등록 | – | 모든 조회 |
| 관리자 | 사업·대회 등록·수정·마감·삭제, 조회, 상태·메모 변경, 삭제, 첨부 열람, 기록 남기기 | 계좌번호 등 신청 원본 수정, 작업 기록 수정·삭제 |

추가 장치
- DB 단계 검증: 학번·전화·계좌 형식, **예금주 = 성명**, **모집중인 사업·대회인지·지급 구분이 맞는지**, 통장 사본 경로가 해당 신청서 것인지, 학번당 하루 5회
- 저장소: 비공개, 5MB, JPG·PNG·PDF만, 정해진 경로만 업로드
- 화면: 콘텐츠 보안 정책(CSP)으로 외부 스크립트·외부 통신 차단, 관리자 토큰은 메모리에만(창 닫으면 로그아웃), 15분 무사용 자동 로그아웃, 자동 입력 프로그램 차단용 숨은 칸
- 엑셀: 모든 칸을 문자로 저장(수식 삽입 공격 차단, 앞자리 0 유지)

> Supabase 주소를 사용자 도메인으로 쓰는 경우 `index.html`·`admin.html`의 `connect-src`에 그 도메인을 추가하세요.

## 5. 운영 전 확인할 사항 (한계)

1. **본인 인증 없음** – 링크를 아는 누구나 신청할 수 있습니다. 허위 신청이나 **남의 학번으로 한 계좌 변경 신청**이 들어올 수 있으므로, [계좌변경] 표시 건은 반드시 본인 확인 후 처리하세요.
2. **개인정보 처리 위탁** – 데이터가 Supabase Inc.(미국 회사)의 서울 리전 서버에 저장됩니다. 동의서에 위탁 사실을 표시했으며, **학교 개인정보처리방침 반영과 위탁·국외이전 해당 여부를 개인정보보호 담당 부서와 확인**하세요.
3. **요금제** – 무료 요금제는 사용량 한도가 있고, 일정 기간 사용이 없으면 프로젝트가 일시 중지될 수 있으며, 백업 정책도 요금제마다 다릅니다.
4. **내려받은 파일** – 엑셀·ZIP에는 계좌번호가 들어 있습니다. 업무용 PC에만 보관하고 사용 후 삭제하세요.
